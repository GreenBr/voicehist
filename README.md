# voicehist

**Windows 本地语音输入 —— 讲过的每一句话都留得住。**

按一个热键讲话，文字直接出现在游标处。完全离线、不上传任何音讯、不用订阅。

跟其他语音输入工具最大的差别：**就算贴上失败、焦点跑掉、视窗关掉，你讲的那段话也一定留在历史里。**

---

## 为什么做这个

Windows 内建的 `Win+H` 有个致命问题：**游标不在输入框时它根本不会启动**，你讲的那段话直接消失，没有任何纪录可以救。

voicehist 的流程刻意反过来：

```
讲话 → 本地转写 → ① 先写进历史 → ② 复制到剪贴板 → ③ 才尝试贴上
```

前两步一定会成功。第三步失败也无所谓，内容还在剪贴板，也还在历史里。

## 特色

| | |
|---|---|
| 🔒 **完全离线** | 用本地 Whisper，音讯不离开你的电脑，没有 API key、没有帐号 |
| 📝 **完整历史** | 每一句都存下来，含时间、长度、语言、**当时你在哪个视窗** |
| 🇹🇼 **中英混用** | 中文句子里夹英文技术名词没问题，输出繁体 |
| ⚡ **够快** | RTX 3050 上，30 秒的话约 1.5 秒转写完 |
| 💤 **不占资源** | 待机时 CPU/GPU 接近 0%，可设定闲置自动释放显存 |
| 🎯 **看得到状态** | 浮动指示灯 + 系统匣图示，随时知道有没有在录 |

## 需求

- Windows 10 / 11
- Python 3.9+（[下载](https://www.python.org/downloads/)，安装时勾选 **Add Python to PATH**）
- 麦克风
- NVIDIA 显示卡（**选配**）—— 有的话会快很多；没有会自动退回 CPU

## 安装

```powershell
git clone https://github.com/GreenBr/voicehist.git
cd voicehist
.\install.ps1
```

装完桌面会出现一个 **voicehist** 图示。

> 第一次启动会下载约 1.5GB 的 Whisper 模型，请等它跑完（之后都是本地读取，很快）。

## 使用

**一个图示就是全部入口。** 双击桌面的 **voicehist** 让它进入待命，之后随时按热键讲话。
程式已经在跑时再点同一个图示，会直接开启历史视窗。

| 动作 | 按键 |
|---|---|
| 启动待命 | 双击桌面 **voicehist** |
| 开始录音 | `Ctrl + 空白` |
| 停止并转写 | `Ctrl + 空白` 或 **`ESC`**（单键，不用按组合键）|
| **取消这一段** | **`Delete`** —— 误触时直接丢弃，不转写、不留纪录 |
| **强制唤醒** | **双击系统匣图示**（热键没反应时用这个）|
| 看历史 | 系统匣图示右键 → 开启语音历史（或再点一次桌面图示）|
| 改设定 | 系统匣图示右键 → 设定 |
| 结束程式 | 系统匣图示右键 → 结束 |

### 状态显示：系统匣图示 + 只在录音时浮现的小视窗

**平常萤幕上什么都没有**，只有系统匣（时钟旁边）一个麦克风图示，它会依状态变色：

| 图示颜色 | 意思 |
|---|---|
| ⚪ 灰 | 待机中，随时可用 |
| 🔴 红 | **录音中** |
| 🟡 黄 | 转写中 |
| 🟢 绿 | 刚完成 |

按下热键开始录音时，右下角会**浮出一个小视窗**显示秒数与音量条，停止後 2 秒自动消失。
可以拖曳到任何位置。

> 音量条不跳 = 麦克风没收到声音，可以立刻分辨是「没在录」还是「录了但没声音」。

想让它一直显示、或完全不显示，在设定里改 `indicator_mode`（`auto` / `always` / `off`）。

### 合盖再打开後热键没反应？

这是 Windows 休眠时会**静默移除低阶键盘钩子**造成的 —— 程式还活著（图示还在），但收不到按键。

voicehist 会自己处理：它每 0.12 秒自检一次，两次相差超过 5 秒就判定系统刚睡醒、**自动重挂热键**。成本是一次减法，没有任何背景轮询。

万一还是没反应，**双击系统匣图示**就是「强制唤醒」—— 重挂热键、指示灯浮上来 3 秒让你确认它活著。不用结束再重开。

### 历史视窗

- 右上角搜寻框即时筛选
- 每则卡片右下角 `⧉ 复制`，点了会变绿显示 `✓ 已复制`
- 卡片任一处点击也能复制
- 没贴上成功的会标 **● 未贴上**
- `F5` 重新载入 · `ESC` 关闭

## 设定

系统匣右键 → 设定，或直接改 `%USERPROFILE%\.voicehist\config.json`。

| 项目 | 预设 | 说明 |
|---|---|---|
| `hotkey` | `ctrl+space` | 启动／停止录音 |
| `stop_key` | `esc` | 额外的停止键，只在录音中生效 |
| `model` | `medium` | 模型档次，见下表 |
| `beam_size` | `1` | **保持 1**。实测调大只会慢 4.6 倍，文字不会变好 |
| `compute_type` | `int8_float16` | GPU 精度。int8 权重让显存从 2.1GB 降到 1.0GB，文字几乎一样，是 4GB 显卡跟 DaVinci Resolve／Chrome 共存的关键；`float16` 是旧预设 |
| `min_free_vram_mb` | `1500` | 载入时显存剩不到这么多 MB 就改跑 CPU。被挤爆的 GPU 会把模型换到主记忆体，比 CPU 慢 10 倍以上。`0` = 永远硬上 GPU |
| `cuda_allocator` | `cuda_malloc_async` | 转写完把 GPU 工作缓冲区还给显卡，闲置时少占几百 MB；`cub_caching` 是 ctranslate2 旧预设 |
| `cpu_threads` | `0` | CPU 模式用几条线程，`0` = 实体核心数 |
| `language` | `null` | 留空 = 自动侦测。中英混用建议留空 |
| `initial_prompt` | 繁中范例句 | **让 Whisper 自己加标点的关键**，见下方说明 |
| `idle_unload_minutes` | `5` | 闲置几分钟释放显存。`0` = 一直常驻 |
| `pause_space` / `pause_newline` | `0.35` / `1.0` | 停顿多久插空格／换行（秒） |
| `auto_paste` | `true` | 转写完自动贴上 |
| `indicator_mode` | `auto` | `auto` 录音时才浮现 / `always` 一直显示 / `off` 只靠系统匣图示 |
| `tray_status_color` | `true` | 系统匣图示依状态变色 |
| `wake_gap_seconds` | `5` | 自检间隔超过这秒数就判定刚睡醒、重挂热键 |
| `ui_scale` / `ui_width_scale` | `1.6` / `1.2` | 指示灯高度／宽度倍率 |

### 热键跟中文输入法打架？

`Ctrl+空白` 在**微软注音／拼音里是「中英文切换」**。两个功能会同时触发（录音正常，但输入法状态也会跟著变）。

觉得困扰的话，把 `hotkey` 改成 `ctrl+alt+space` 就完全不打架。

## 关于标点符号

Whisper 转中文时**预设不太加标点**（[已知问题](https://github.com/SYSTRAN/faster-whisper/issues/662)）。voicehist 用两个方法处理，互补：

**1. `initial_prompt` 引导** — 在前面喂一句带标点的范例，Whisper 就会照著加：

```
不给：看起來效果還可以但是那個字有點太小圖示可不可以放大到現在的三倍
给了：看起來效果還可以，但是那個字有點太小，圖示可不可以放大到現在的三倍
```

顺带一提这也会让它偏向输出**繁体**。

**2. 照停顿还原空格／换行** — Whisper 回传的 segment 本来就是照你的停顿切的，voicehist 会依实际间隔还原：

```
看起來效果還可以 但是那個字有點太小
圖示可不可以放大到現在的三倍 然後那個紅點不要一直閃爍
```

> 想要更强的排版（去赘词、自动分段、条列化），那需要接一层 LLM 后处理 —— 这正是 Wispr Flow 那类付费工具在做的事（Whisper 转写完再丢给 fine-tuned Llama）。voicehist 目前不做这层，因为它会牺牲「完全离线」和「低延迟」。

## 模型档次

| 档次 | 参数量 | 说明 |
|---|---|---|
| `tiny` / `base` | 39M / 74M | 很快，但中文不堪用 |
| `small` | 244M | 快，但中文会掉准（实测把 `Log` 听成 `LOD`，且输出简体）|
| **`medium`** | **769M** | **预设。4GB 显卡的甜蜜点，输出繁体** |
| `large-v3` | 1550M | 最准，但 4GB 显存不够 |
| `large-v3-turbo` | 809M | 名字有 turbo，实测长音讯反而**慢 3.5 倍**，且输出简体 |

## 资源占用（RTX 3050 4GB 实测）

| 项目 | 待机 | 讲话时 |
|---|---|---|
| GPU 使用率 | **1~3%**（等于没用） | 短暂拉高 1~2 秒 |
| CPU | **≈0%** | 极短 |
| 记忆体 | **430 MB** | 同 |
| 显存 | **1.0 GB**（`int8_float16`；旧预设 `float16` 是 2.1 GB） | 同 |

**待机时完全不吃 CPU/GPU**，只在讲完话后动 1~2 秒。

打游戏时嫌那 1.6GB 显存碍事的话，`idle_unload_minutes` 预设就是 `5` —— 闲置 5 分钟自动释放，下次按热键约 2.4 秒载回，准度不变。

### 转写速度（medium, beam_size=1）

| 讲话长度 | 转写耗时 |
|---|---|
| 7.5 秒 | 0.94 秒 |
| 30 秒 | 1.51 秒 |

> 这是显存充裕、显卡全速时的数字。每次转写的实际耗时都会写进 log（`⏱ 转写 2.1s（音讯的 0.07 倍，GPU）`）和 `history.jsonl`（`trans_s`），变慢时看那一行就知道。正常是音讯长度的 0.05～0.2 倍。

## 疑难排解

**按热键没反应**
系统匣有麦克风图示吗？没有 = 程式没在跑，双击桌面的 voicehist。有的话先**双击那个图示**强制唤醒（合盖睡醒後钩子会掉，这一下就修好）。还是不行，可能是热键被中文输入法吃掉了，改成 `ctrl+alt+space`。

**转写突然变很慢（讲 30 秒要等 30 秒以上）**
几乎都是显存被别的程式挤满了。4GB 显卡上 DaVinci Resolve 一开就吃 2.7GB，Chrome、dwm 再各拿几百 MB，模型被 Windows 换到主记忆体，速度掉 10～60 倍（实测 37 秒的话从 3 秒变 254 秒）。voicehist 会在 log 写一行 `[慢] …显存 3755 / 4096 MB，最占的是 Resolve 722MB…` 告诉你是谁；载入时剩不到 `min_free_vram_mb` 就自动改跑 CPU。关掉那个程式，下次载入会自动回 GPU。
另一个原因是显卡被限功耗：`nvidia-smi -q -d POWER` 看 `Current Power Limit`，Legion 笔电接到瓦数不够的变压器（或 USB-C 充电）时韧体会把 GPU 压到 20W（预设 60W），转写慢 3～4 倍。换回原厂变压器就恢复。

**指示灯变红但音量条不跳**
麦克风没收到声音。到 设定 → 系统 → 音效 → 输入，确认预设装置正确、音量不是 0、没静音。

**重复双击会开好几个吗**
不会。有单例锁 —— 而且第二次点会直接把历史视窗叫出来，不是静静没反应。

**关掉程式**
系统匣图示右键 → 结束。显存和记忆体立刻释放。

**看 log**
`%USERPROFILE%\.voicehist\voicehist.log`

**取消开机自动启动**
删掉 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\voicehist.lnk`

## 档案位置

```
%USERPROFILE%\.voicehist\
├── voice.py           主程式（热键、录音、转写、指示灯、系统匣）
├── history_gui.py     历史视窗
├── settings_gui.py    设定视窗
├── make_icons.py      产生图示
├── config.json        你的设定
├── history.jsonl      语音历史（一行一则 JSON）
├── voicehist.log      执行纪录
└── venv\              虚拟环境
```

历史是纯 JSONL，想自己拿去处理很容易：

```json
{"ts":1756270000,"time":"2026-08-27 14:30:00","text":"帮我重构那个 middleware","lang":"zh","seconds":8.2,"window":"Windows PowerShell","pasted":true}
```
